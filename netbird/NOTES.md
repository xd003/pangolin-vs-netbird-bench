# NetBird 0.82.0 benchmark stack

Compose project `nb`. Subnets: `wan` 10.88.X.0/24 (bridge), `sitelan` 10.89.X.0/24 (internal),
X = `NET_ID`. Dev run: `NET_ID=2 NAME_SUFFIX=-nbdev`.

## Run

```
NET_ID=2 NAME_SUFFIX=-nbdev ./up.sh               # default: direct P2P, kernel WG
RELAY=1 NET_ID=2 NAME_SUFFIX=-nbdev ./up.sh       # private path forced via relay
WG_USERSPACE=1 NET_ID=2 NAME_SUFFIX=-nbdev ./up.sh # site + client on userspace WG
./down.sh                                          # containers, networks, volumes, state/
. ./env.sh                                         # exports PRIVATE_TARGET, PUBLIC_RESOLVE, ...
```

`up.sh` exits non-zero unless the requested connection type and WG interface type are observed and
the smoke checks pass. Everything is driven via the management REST API, invoked from `loadgen`.

## Versions

- `netbirdio/netbird-server:0.82.0` as `nb-server` (management + signal + relay over WS on :8080 + STUN :3478 + embedded IdP)
- `netbirdio/reverse-proxy:0.82.0` as `nb-proxy`
- `netbirdio/netbird:0.82.0` as `site` (routing peer for 10.89.X.10/32) and `client`

## Objects created by up.sh

- Groups `bench-sites` (site setup key auto-group), `bench-clients` (client key), `bench-target` (resource group)
- Network `bench-site-lan` with resource `10.89.X.10/32` (type host) and router `peer_groups=[bench-sites]`, masquerade on, metric 9999
- Policy `bench-clients-to-target`: source `bench-clients` -> destinationResource host, protocol `all`, bidirectional, accept
- Proxy cluster `bench.test` (from `NB_PROXY_DOMAIN`); service `app.bench.test` (mode http, no auth, private=false),
  one target `target_type=host`, `target_id=<resource>`, port 80 (management resolves host to 10.89.X.10)

## Data paths (observed)

Private (`client-tools` -> wt0 -> site -> sitelan -> target). Single routed hop: ping TTL is 63 on the client side.

| Mode | client<->site | Connection type (client `netbird status -d`) | WG on client | WG on site |
|---|---|---|---|---|
| default | direct P2P | `P2P`, ICE host/host | kernel (`wireguard` link) | kernel |
| `RELAY=1` | relayed via `rel://nb-server:8080` | `Relayed`, ICE -/- | kernel | kernel |
| `WG_USERSPACE=1` | direct P2P | `P2P`, ICE host/prflx | userspace (`wt0` is `link/none` tun, `pfifo_fast`) | userspace |

Public (`loadgen` -> `nb-proxy:443` -> embedded netbird tunnel -> site -> target `/1k`). Verified byte-identical
to the target's file (md5 match), certificate `CN=bench.test` (static, `*.bench.test` SAN).

| Mode | proxy<->site | WG on proxy | WG on site |
|---|---|---|---|
| default | direct P2P (site: `proxy-... Connection type: P2P, host/host`) | userspace (netstack, in-process) | kernel |
| `RELAY=1` | **relayed** (site: `Relayed`, `rel://nb-server:8080`) | userspace (netstack) | kernel |
| `WG_USERSPACE=1` | direct P2P | userspace (netstack) | userspace |

Notes on the proxy:
- The reverse-proxy's embedded client always runs in netstack mode: `proxy/internal/roundtrip` never sets
  `NoUserspace`, and the proxy log config dump shows `no_userspace: false`. The proxy netns has only `eth0`,
  i.e. no kernel WG device. `WG_USERSPACE` and `NB_WG_KERNEL_DISABLED` therefore do not affect the proxy.
- Under `RELAY=1`, only `client` and `site` get `NB_FORCE_RELAY=true`. The proxy still reaches site through relay
  because site (forced) has no ICE listener [INFERENCE from `proxy/internal/roundtrip` and `client/internal/peer/conn.go`:
  forced peers skip the ICE worker]. Observed result: proxy-to-site is `Relayed` as well.

## Kernel vs userspace per component

- `site`, `client`: kernel WG (`wireguard` link) by default. `NB_WG_KERNEL_DISABLED=true` (WG_USERSPACE=1) gives userspace (`Interface type: Userspace`).
- `nb-proxy`: always userspace netstack (see above).
- `nb-server`: no WG.

## Non-default settings

- `NB_LAZY_CONN=off` on `nb-proxy`. Without it, the site peer stays `Idle` and the public path returned
  HTTP 502 "Request Canceled" for minutes: the proxy's dials do not wake the lazy site peer. Client and site
  keep NetBird's default (lazy on), so the first private probe wakes the tunnel (`up.sh` polls).
- Removed the auto-created `Default` All<->All policy via API (`DELETE /api/policies/<id>`). The YAML key
  `disableDefaultPolicy` is not read by the combined server (`Management` is `yaml:"-"`), so it cannot be set from config.
- `NB_PROXY_DOMAIN=bench.test`, so `app.bench.test` is a subdomain of the proxy cluster. The static cert is a
  self-signed `CN=bench.test` with SAN `bench.test,*.bench.test` (P-256, generated by `up.sh`) and is copied into
  the `nb-certs` volume. The proxy binds :443 as non-root without extra sysctls.
- `NB_RELAY_TRANSPORT=ws` on all netbird processes (combined server serves relay on WebSocket :8080, no QUIC), `NB_PROXY_ALLOW_INSECURE=true` (plain-HTTP management).
- `NB_SETUP_PAT_ENABLED=true`, `NB_DISABLE_GEOLOCATION=true`, `disableAnonymousMetrics`, `disableGeoliteUpdate`: as in netbird/e2e/harness.
  The proxy keeps GeoLite download on (default); it needs egress to pkgs.netbird.io (worked here).
- Routing peer: `masquerade: true`. The target has no default route (sitelan is internal), so its replies go to site's sitelan IP (on-link). [INFERENCE: design rationale, not separately tested without masquerade.]
- `site` sets `sysctls: net.ipv4.ip_forward=1` (netns-scoped). NetBird also sets it itself.
- Store and proxy cert live in named volumes (`nb-data`, `nb-certs`), not bind mounts. Bind mounts of a host
  directory that `down.sh` deletes and `up.sh` recreates produced `unable to open database file` in nb-server.
- Smoke durations are short (iperf3 -t 2, rtt 2s, one 1 MiB curl). These are path checks, not benchmarks.
- Private access is all protocols (`protocol: all`), so ICMP works (`ping` ok, TTL 63).

## Limitations / observations

- Proxy's own WG is userspace in all modes; WG_USERSPACE does not change it (contract only asked for site+client).
- Lazy connections: first probe after `up.sh` (or after idle) pays a handshake; warm up before timing.
- `RELAY=1` forces relay on `client` and `site` only; proxy-to-site ends relayed as a consequence (observed).
- No host ports are published. Everything runs via `docker exec` into `client-tools`, `loadgen`, `client`, `site`, `nb-server`.
- Container names: `nb-server`, `nb-proxy`, `site`, `client`, `client-tools`, `loadgen`, `target` + `${NAME_SUFFIX}`.
